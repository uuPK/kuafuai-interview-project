| 验收目标 | 离线结果与边界 |
| --- | --- |
| 工具成功与失败正确反馈 | 响应先保存、工具按序执行、每个调用 ID 配对；未知工具、参数/权限错误、结果过大、提交后剩余调用均有结构化反馈 |
| 反馈驱动下一步行动 | 脚本模型读取零结果后改用英文查询，抓取失败后换来源，替身提交拒绝后修订；这些验证协议与循环行为，真实模型决策待验收 |
| 预算与截止时间持久化 | 模型每次尝试扣预算，工具重试只扣一次逻辑调用；计数先保存，恢复保留新闻窗口、首次开始时间与截止时间；接近上限提醒并预留最后决策和提交名额 |
| 有限重试与等待 | 每个安全外部请求最多三次尝试；指数退避兼容 Retry-After 秒数/HTTP 日期；默认等待超过 5 秒保存 waiting_retry 并返回，到期后继续同一请求；鉴权/额度/配置/协议错误停止无效重试 |
| 重复失败与上下文边界 | 同一动作连续失败三次后提醒，再次重复停止；同批第四次先阻止并补齐反馈，再给模型提醒；零结果计入连续无效行动；输入超限停止并保留完整消息 |
| 数据库与中断边界 | v3→v4 保留历史消息、响应、调用与窗口；升级失败回滚；调用计数/尝试、响应/调用列表、结果/反馈/完成状态协调保存；已知等待和已保存结果可继续，执行结果不确定的调用保留恢复标记 |

综合轨迹见 `test_phase_one_feedback_retry_and_recovery_trace`：零结果 → 模型限流等待 → 重开数据库 → 英文补查 → 抓取失败 → 换来源 → 替身提交拒绝 → 修订提交。轨迹使用 7 次模型尝试、2 次逻辑搜索、2 次逻辑抓取和 6 次工具调用，恢复前后截止时间一致，所有调用 ID 配对完整。

本阶段提交工具仍为显式注册的离线替身；正式新闻规则、模型核对及执行结果不确定时的 Worker 接管按阶段 3 实施。实际 DeepSeek/博查 HTTP 状态映射分别在 2.1/2.2 接入。本次未调用真实模型、搜索或邮件服务，相关联通状态保持待验收。
