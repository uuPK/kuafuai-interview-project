# 项目交付与人工测试入口

本项目实现了模型自主工具调用、结构化反馈后补查、规则与独立模型核对、一次修订、持久恢复，以及登录/订阅/预览/历史、北京时间调度、SMTP 和容器部署。部署操作见 [deployment.md](deployment.md)，可复现验收见 [core-acceptance.md](core-acceptance.md)，逐次实测和未通过记录见 [acceptance.md](acceptance.md)。README 按用户协作约束保留。

## 启动与使用

已有本地 .env 已配置模型、搜索、会话与 QQ SMTP 参数；它不进入 Git，也不进入镜像。其他电脑从 .env.example 创建自己的配置。Windows 中文目录先运行 `python scripts/build_images.py`，随后 `docker compose up -d --no-build --wait api worker`；页面为 http://127.0.0.1:8000/。首次启动初始化命名卷数据库；原生 ./data 的迁入按部署说明操作。页面无内置账号，需注册。

当前 SMTP_TEST_RECIPIENT 限定唯一测试收件人。测试账户用该地址注册或修改资料，保存话题、关注词、排除词和条数。预览生成后保留在历史中，不自动发信；在简报详情点击“发送这份简报到邮箱”可手动投递。订阅设置可修改每日邮件生成时间（北京时间），到点开始生成并在完成后自动发送。收件邮箱在个人资料中设置，保存后生效。缺乏可用新闻时允许有依据的空简报；外部服务故障在页面显示简短失败原因，具体记录由后端保留。

修改 .env 后重建容器才会重新注入配置：`docker compose up -d --no-build --force-recreate api worker`。单纯 restart 保留旧环境。当前容器健康只表示进程与 Worker 心跳正常。

## 人工测试顺序

2026-10-20 已完成前端五步改版并更新本地镜像：今日简报、历史简报和订阅设置独立导航，资料置于账户菜单；新闻优先阅读，引用依据可展开。37项前端测试、133项相关Python回归和浏览器交互通过，详细记录见acceptance.md。实际模型本轮有一次不完整响应失败，页面保留旧内容并提供重新生成；成功交互另用独立替身验收。

1. 注册、退出后登录，保存资料与订阅；刷新后数据仍存在。另建账号检查历史隔离。
2. 从今日简报生成预览或重新生成，等待期间继续阅读旧内容；完成后点击阅读新简报。历史按实际生成日期保存每次结果，可分页、直达详情、刷新与返回。时间缺项说明默认可见，引用依据可展开；待核实信息单列简介、具体疑点与原文链接，明确简介尚未核实。生成完成不应打断阅读或收回已加载历史分页。
3. 选择不同偏好，核对选题理由、排除词及未覆盖话题说明；中英文来源均以中文整理。
4. 暂停订阅，确认新预览/调度/邮件被阻止；恢复并设置未来时间验证定时生成、日唯一和邮件状态。unknown 必须确认重复风险后才会重发。
5. 重启 API/Worker 后读取历史简报，正在生成的任务继续展示必要状态；再按部署说明在独立新卷演练备份恢复。

这五步包含外部服务。Fake-IP 网络可使用部署说明中的 `PUBLIC_DNS=google_doh`，当前本地实例已启用；RSS 默认关闭，按需通过 `RSS_ENABLED=true` 启用补充来源。纯替身轨迹与接口回归可独立运行。五份真实新闻简报的人工审阅逐条检查：摘要和关键事实是否被完整正文支持、数字/单位/比较条件、引用字符位置、确认日期是否落入固定窗口、日期缺项说明是否清楚、待核实候选是否有具体原因与原文链接、偏好与中文表达、历史是否已有相同事实，并记录发现的问题。

新显示规则用于新生成的简报。时间缺项可以标注后显示，明确超窗的内容放在补充待核实信息中；主新闻仍须有正文依据与准确引用。事实存疑时先补查以尽量达到设定条数，仍未确认的候选附后，不计主新闻条数、不写入已交付事实历史。旧待核实记录阅读时从原始草稿、检索摘要或原文节选补充简介；数据库原文与已入队邮件保持固定。

2026-10-18 用户已批准最终交付调整：第二次取得有效事实核对拒绝时，服务端仅交付带原文标题、核对问题与链接的待核实线索，明确未确认任何主新闻。被拒绝的摘要与关键事实不进入交付事实历史。权限、引用不一致、损坏材料、核对输入不足、服务或协议故障继续按错误处理；旧失败任务保持原记录，新规则用于新生成任务。最新实测见 acceptance.md。
